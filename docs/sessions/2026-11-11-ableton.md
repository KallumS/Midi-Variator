# 2026-11-11 - Live's colours and a MIDI Tool

The user asked for the Ableton versions to look like Ableton, using the Ableton-inspired scheme tried before, and whether the generators could be MIDI Tools in Live's Generate and Transform panels.

- **Colours**: the scheme is Starting Blocks' Live 8 theme of 18 September (commit 2765b0a3, found in its history, not on any branch), now `ableton/kit/palette.js`. Two changes to it for 7:1 words: the chrome a step darker (#3E3E3E) and light buttons with dark ink. Everything is drawn through `UI.C`.
- `kit/test/palette_suite.js`: every word 7:1 on every surface, edges 3:1, the greys neutral, the house scheme translated without losing a contrast. Each rule was broken on purpose; the yellow-shade rule was missed at first (the check only asked that the shade was lighter) and now asks that it is amber.
- **A MIDI Tool** for the Transform panel, `ableton/tool/`: the same engine, adapter and kit as the device. Its file type (`natt`) is from Ableton's `maxdevtools`; the notes and context `live.miditool.in` hands over are from MidiShower, an open-source tool, because docs.cycling74.com could not be reached.
- `kit/test/tool_suite.js`, `tests/test_tool.js`. Broken on purpose: the file type, the fill, the re-apply (and re-applying before any apply), the clip's key, the suggestion's originals, cutting at the selection's end, saving, the seed, the nothing-selected message. Two missed at first: the cut (no Good Idea idea crosses the end of an 8-beat selection, so the test now uses 6.5 beats; Starting Blocks catches it) and the nothing-selected message (the engine's own message also starts with "Select", but says "score", not Live's word; the test now asks for the tool's own).
- Not done: opening either in Live. The first thing to check there is that the tool appears under its panel and that the dictionaries' keys are as assumed.
